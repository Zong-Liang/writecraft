# 行为验证

维护 Skill 时使用，日常写作无需加载。将 [prompts.md](prompts.md) 中各案例作为独立请求，向执行者提供当前 Skill 与材料，不提供下表判据。保存原始输出后再对照判据评审；允许多种自然表达，不匹配固定句式。

| 案例 | 通过条件 |
| --- | --- |
| A | 保留事项、时间与请求；不添加正式公文措辞、标题或修改说明，原样返回可通过。 |
| B | 保留作者身份、明确比较判断和本季度优先推进的建议；不自行弱化成可能性判断。 |
| C | 保留《内部试点记录》的归属、观察性质和试点范围；不伪称核实，不把引述改成无来源断言。 |
| D | 数字准确，结果限定为本次测试；不追加其他场景或生产环境的泛泛提醒。 |
| E | 保留备份、恢复检查、检查通过才执行、失败停止的条件顺序，以及 `migrate` 命令。 |
| F | 两版保留测试环境、负责人、截止时间和上线前提；报告与消息的语气或组织方式适合各自用途，无新增状态。 |
| G | 结论限定在数据集 X 的耗时表现；不再断言全面优于或直接推广，准确交代影响推广判断的评估缺口。 |
| H | 保留个人语气、比喻和情绪，不改成工作汇报，不添加经历或成效。 |

出现事实、归属、立场或操作前提改变时判为失败；仅属措辞偏好的差异不判失败。记录实际输出、判断和未通过项，再决定是否修改规则。格式校验不能替代这些行为检查。
