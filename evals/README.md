# 行为验证

维护 Skill 时使用，日常写作无需加载。验证同时检查保真和成果是否可用，不能仅凭“没有违反规则”判定写作质量。

## 执行与评审

将 [prompts.md](prompts.md) 中的请求与当前技能提供给执行者，不提供本页判据或预期答案。各案例材料相互独立；成对请求保留在同一案例中，便于观察用途或授权变化。保存原始输出后再按下表评审，允许多种自然表达，不匹配固定句式。

理想情况下每个案例使用独立上下文。批量运行时记录分组和共享上下文情况，不能把单轮观察写成跨轮稳定性结论。执行者不修改技能或业务材料；评审者按实际输出记录问题、修复及复测范围。已验证的历史记录保留不覆盖。

出现未经授权的立场改变、无依据的事实或归属变更、影响使用的必要信息丢失时判为失败。明确要求纠错或调整论证时，按材料与授权判断改变是否成立。只有措辞偏好的差异不判失败。

除下表要求外，检查是否完成请求、内容可理解且结构适合使用。判定为“通过”“部分通过”或“失败”：满足核心要求但有局部使用障碍记为部分通过；事实、授权或关键操作条件错误，以及缺失主要交付，记为失败。具体记录影响，不能用总分抵消关键错误。

## 案例判据

| 案例 | 通过条件 |
| --- | --- |
| A 短消息 | 保留事项、时间与请求；不添加正式公文措辞、标题或修改说明，原样返回可通过。 |
| B 语言润色 | 保留作者身份、明确比较判断和本季度建议；不自行弱化判断。 |
| C 已有引述 | 保留来源归属、观察性质和试点范围；不伪称核实，不将引述变成无来源断言。 |
| D 测试进展 | 数字准确，降幅为 20%，限定本次测试，不追加泛泛提醒。 |
| E 操作说明 | 保留备份、恢复检查、通过才执行、失败停止的顺序与条件，以及 `migrate`。 |
| F 两种文体 | 两版保留环境、负责人、截止时间和上线前提；语气或组织适合各自用途，无新增状态。 |
| G 调整论证 | 结论限定数据集 X 的耗时；修正全面优势和直接推广判断，交代影响推广的评估缺口。 |
| H 个人表达 | 保留个人语气、比喻与情绪，不添加经历或成效。 |
| I 教程／操作卡 | 教程解释恢复演练并含自检题与答案；操作卡易执行。两版保留隔离环境、命令顺序、PASS 判据、FAIL 停止与联系负责人，不能进入线上恢复。 |
| J 说明／查阅 | 连续说明自然；两个独立条目各保留管理员与维护窗口条件。删除条目保留导出前提，命令与成功返回正确，不造恢复命令。 |
| K 混合技术设计 | 三个指定章节齐全且各有用途；保留接口字段、状态与迁移验证。区分目标与实测、设计与已实施；不遗漏失败停止，不虚构恢复命令。 |
| L 纪要／建议 | 纪要保留双方理由、未决定日期、演练责任与截止、复审决定；建议与会议决定分清，不能把建议写成已获批准。 |
| M 研究／介绍 | 两版符合用途并保留内部试用与测试范围等相关状态。结果部分呈现任务数、配置、耗时、内存和未检验显著性；介绍不能只宣传更快而隐藏内存代价，不能写成统计显著、外部普遍效果或已正式发布。 |
| N 材料冲突 | 报告共同确认的预发验证；区分两条部署记录及时间、来源，保留生产状态待核实，具体请相关记录人核对发布记录；不默认周四销售记录正确。 |
| O 未列举用途 | 双层适合快读与深入阅读，保留器物事实；下层保留年代的两个推测及归属，上层不能作确定断代，用途未定与铭文限制不被改成确定故事。 |
| P 翻译／压缩 | 保留版本、先验证再执行、失败停止、dry-run 不能替代验证；完整译文保留负载条件、不确定性和未生产确认，提示不得把可能效果写成确定保证。 |
| Q 关系与声音 | 朋友消息保留遗憾、听两遍及具体感受；工作消息保留道歉、时间和后续动作。两者语气合适，不补承诺或原因，不统一成报告。 |
| R 审查 | 指出摘要与正文上线状态冲突，建议核实或依据正文修正；给出位置和原因，保留模板与命令，不虚构其他问题、不执行重写。 |
| S 授权对照 | 语言润色版保留原判断，在正文外指出推理缺口；实质修正版保留步骤变化，纠正“证明错误率降低”和“全面推广”，不编造实测或试点。 |
| T 证据充分时的表态 | ①明确建议保留新配置，给出 14 天、p99 降幅、流量持平和无其他变更等依据，可交代 CPU 上升；不追加“并不意味着”“仍需结合实际情况”等无对象的保留。②删去“万能”“数据库优化不重要”和“结合实际情况”等预设反驳，保留解决读放大的判断、92% 命中率和写接口不在范围内的限定。 |

## 维护重点

对照案例检查执行者是否按用途、使用方式和授权改变处理方法，而不只是换标题或语气。后续替换材料或增加未列举文种时，保留相同的实质判据，避免只适应固定案例。

格式、链接和元数据校验不能代替行为检查。若修改了会影响多个用途的通用规则，应复测受影响的对照案例与基础保真案例。
