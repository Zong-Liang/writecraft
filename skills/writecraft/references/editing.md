# 专业编辑与双语表达

## 诊断问题，再决定改动

| 原文的问题 | 改动依据 |
| --- | --- |
| 「显著提升效率」缺少测量结果 | 写出已知机制或变化。例如「测试数据准备与用例执行分开，失败用例可以独立重跑」。有耗时数据时再交代比较口径和结果。 |
| 「研究表明」「普遍认为」缺少归因 | 核实并写出具体来源及其支持范围。无法核实时删去归因，并按证据收紧判断。 |
| 段首转场重复，标题对称但内容单薄 | 保留需要的转折、对比或递进。其余部分直接写事实或将职责相同的段落合并。 |
| 术语让读者难以理解 | 必要时解释术语对应的对象、机制或实际动作。术语本身有准确的专业含义时保留。 |
| 文稿出现假悬念、假互动或助手式开场 | 删去与交付内容无关的铺垫，直接交代读者需要知道或执行的事项。 |

以具体的信息损失或阅读障碍判断改动。词频、句长和检测器分数无法判断某句话是否准确或合适。作者的个人经历、情绪和口头习惯应有材料依据。

## 按语言和文体校准表达

先遵守当前任务的风格要求。需要参考作者风格时，优先看同类文体的成熟样稿，再看其他作品和当前稿件中稳定的表达习惯。缺少样本时按读者与用途选择中性语体。

- **中文**。明确谁做了什么、涉及什么对象、在什么条件下成立。抽象名词密集时拆回动作和关系。技术文档保留必要的规范措辞和并列步骤。
- **英文**。保留有明确技术含义的措辞，例如 `robust` 用于有相应依据的稳健性描述。收紧模糊归因、夸大的收益和可删去的通用转场。
- **双语与翻译**。先核对术语、否定、情态、程度、归因、比较对象和限定条件，再重排语序。保留可追溯的术语对应关系和原始引文位置。例如，`may reduce retries under load` 可以译为「在负载下可能减少重试次数」，同时保留条件和不确定性。

## 对照原文复查

- 核对研究或调研的样本、指标和条件，避免把相关性写成因果、把局部结果写成普遍结论、把可能性写成已证实的结果。
- 核对动作由谁执行、完成到什么状态。摘要中的提议、决定、负责人和待办要各归其位。
- 核对引文与链接是否仍指向其所支持的句子。对带代码和模板的文稿，同时对照不可改动的技术标识和结构化区段。
